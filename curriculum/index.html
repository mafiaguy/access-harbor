Research map: security · computer science · cloud · SRE · DevOps

01Security 1014–6 hours · breadth first · beginner

Capstone: write a risk review for a fictional course service, covering assets, trust boundaries, identity, application risks, detection, and recovery.

  1. Security goals, assets, threats, weaknesses, and risk scenarios.
  2. Processes, least privilege, network requests, DNS, HTTP, and TLS.
  3. Authentication, authorization, sessions, MFA, secrets, encryption, and backups.
  4. Application security, dependencies, secure configuration, logging, incident response, and recovery.

Video, reading, and PDF sources

NIST CSF 2.0 · overview, videos, PDFUse the six functions to organize an introductory security review. OWASP Top 10 · web readingA shared vocabulary for common web application risk categories. OWASP Cheat Sheet Series · readingsPractical secure development guidance, selected by lesson. OWASP WSTG · guide and PDFUse selected sections only in a deliberately authorized lab. NIST SP 800-61 Rev. 3 · PDFIncident response recommendations and their connection to CSF 2.0. OWASP Video Portal · videosChoose an accessible introductory application security talk.
02Computer Systems Foundations18–24 hours · no experience required

Capstone: document a beginner development setup and trace a browser request from DNS lookup to HTTP response.

  1. Data representation, CPU, memory, storage, and operating-system purpose.
  2. Processes, filesystems, users, permissions, and safe troubleshooting.
  3. Linux shell, paths, files, pipes, processes, and basic scripts.
  4. IP, ports, DNS, routing, HTTP, TLS, browsers, and servers.
  5. Programming fundamentals, Git, error messages, and technical documentation.
  6. Environment configuration, logs, backup, and an integrated system map.

03Cloud Engineering12–16 hours · foundations to guided architecture

Capstone: design a small web service and review its architecture, threats, cost assumptions, and operations.

  1. Cloud models, regions, shared responsibility, elasticity, and cost.
  2. Virtual machines, containers, serverless, scaling, and health checks.
  3. Virtual networks, subnets, routing, DNS, firewalls, load balancing, and edge delivery.
  4. Object/block/file storage, data services, durability, backup, and retention.
  5. Identity, least privilege, secrets, encryption, governance, and budgets.
  6. Observability, failure scenarios, architecture decisions, and runbook.

Video, reading, and PDF sources

AWS Overview · reading and PDFPublisher-maintained overview of cloud services and core platform concepts. Google Cloud Well-Architected FrameworkArchitecture guidance across security, reliability, performance, cost, and sustainability. Google Cloud architecture playlist · videosArchitecture examples and practitioner case studies. Cloudflare Learning Center · reading and videoProvider-neutral introduction to cloud computing and service models.
04Site Reliability Engineering14–18 hours · applied operations

Capstone: define an SLI/SLO, interpret a sample dashboard, and run a tabletop incident review.

  1. Service boundaries, user journeys, dependencies, failure modes, toil, and ownership.
  2. Availability, latency, correctness, indicators, objectives, and error budgets.
  3. Metrics, logs, traces, symptom-based alerts, dashboards, and debugging.
  4. Incident roles, mitigation, communication, timelines, and learning reviews.
  5. Progressive delivery, rollback, overload, redundancy, backup, and capacity.
  6. Safe automation, runbooks, production readiness, and capstone presentation.

Video, reading, and PDF sources

Google SRE · Embracing RiskWhy reliability goals should be balanced against feature delivery and operational cost.
05DevOps & Deployment14–18 hours · hands-on delivery

Capstone: build and test a sample application, package a container, write a deployment plan, and demonstrate rollback.

  1. Git branches, review, merge conflicts, tags, and release notes.
  2. Build/test automation, artifacts, pipeline triggers, and failure diagnosis.
  3. Least-privilege pipeline tokens, secrets, dependencies, and provenance.
  4. Container images, Dockerfiles, ports, volumes, configuration, and health checks.
  5. Environments, rollout strategies, infrastructure as code, and rollback.
  6. Logs, delivery feedback, deployment safety, and capstone runbook.
